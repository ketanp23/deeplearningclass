Deep learning · Chapter 9 · Interactive convolutional-network playground

Look local,
share everywhere.

A convolutional network is a neural network that assumes its input has grid-like structure — a row of audio samples, a grid of pixels, a stack of video frames — and bakes that assumption straight into its wiring. Instead of connecting every input to every unit, it slides a small filter across the grid, reusing the same handful of weights at every position. Three ideas do all the work: connections are local (each unit looks at a small patch), weights are shared (the same filter runs everywhere), and pooling makes the answer robust to small shifts. Those constraints slash the parameter count, respect the geometry of the data, and gave computer vision its modern era. Every filter, feature map and receptive field below is computed live in your browser.

Role · significance · society · §9 intro

Why Convolutional Networks?

Suppose you feed a 256×256 colour photo to an ordinary fully-connected layer. Every one of the ~197,000 input values connects to every hidden unit, so a single modest layer of 1,000 units already carries ~197 million weights — and none of them know that two neighbouring pixels are related, or that a cat is still a cat when it moves ten pixels to the right. A convolutional network throws out that wastefulness by exploiting the one thing images, audio and video all share: grid structure with strong local correlation. It wires up small local filters, reuses them across the whole grid, and pools their responses. The result is a model with far fewer parameters, built-in respect for spatial layout, and tolerance to small translations — the combination that finally made vision work.

In plain words GRADE 6

The picture: imagine you have one small, clear stamp that says "this looks like an edge." Instead of hiring a different inspector for every single spot on a giant photo, you take that one stamp and press it everywhere, sliding it across the whole picture. Wherever the picture matches the stamp, you get a bright mark. That is what a convolutional network does — one small pattern-detector, reused all over the image.

Because the same stamp works in every corner, the network needs to learn only a few stamps instead of millions of separate wires. And because an edge looks like an edge whether it's top-left or bottom-right, the network naturally handles a picture even when things move around a little. Fewer things to learn, and it doesn't get confused when the subject shifts — that's the whole trick, and it's why cameras, phones, hospitals and satellites all rely on these networks now.

What a dense layer gets wrong on images
  • Parameter explosion — full connectivity ties every pixel to every unit; the weight count grows with image size and blows up memory and data needs.
  • No sense of place — a dense layer sees a flat list of numbers; it has no idea which pixels are neighbours, so it must re-learn "nearby matters" from scratch.
  • No shift tolerance — move the object a few pixels and every input changes, so a dense layer must learn the object separately at every location.
  • Data-hungry — with nothing built in, it needs far more labelled examples to reach the same accuracy.
What convolution builds in The three fixes

Sparse (local) connectivity — each unit reads only a small patch, so the wiring is cheap and matches how images actually carry information locally.

Parameter sharing — the same filter runs at every position, so a feature learned once is available everywhere, cutting parameters dramatically.

Pooling / equivariance — sliding a filter makes the feature map move with the input (equivariance), and pooling then makes the summary ignore small moves (invariance).

Representative data, honest evaluation across groups, human oversight for high-stakes calls, and clear limits on deployment are part of doing this well — not optional extras.

The takeaway: CNNs are a genuinely broad tool for societal good, but their benefit depends on who is in the data and how the system is used.

The core operation · §9.1

The Convolution Operation

Convolution is a way of blending two functions: you take a small array of weights — the kernel — slide it over the input, and at each position record the weighted sum of the input values it covers. That single number measures how strongly the input near that spot matches the kernel's pattern. Sweep the kernel over the whole grid and you get a feature map: a new image whose bright spots mark where the pattern was found. In machine-learning libraries the kernel is not flipped, so what we actually compute is technically cross-correlation; the distinction rarely matters because the kernel is learned.

In plain words GRADE 6

The picture: lay a small see-through tile printed with a pattern on top of a photo. At each spot, multiply what's on the tile by what's under it and add it all up — one number saying "how well did the tile match here?" Now slide the tile one step and do it again, across the whole photo. The grid of match-scores you collect is a brand-new picture that lights up wherever the pattern appears.

Change the tile's pattern and you detect a different thing: one tile finds vertical edges, another finds blur, another finds bright dots. The network's job is to learn which tiles are worth having.

03
Why it works · §9.2

Motivation: Sparse, Shared, Equivariant

Convolution improves a machine-learning system through three mechanisms working together. Sparse interactions: because the kernel is small, each output depends on only a few inputs, so we store fewer weights and do less arithmetic. Parameter sharing: the same kernel is used at every position, so we learn one set of weights instead of a separate one per location. Equivariance to translation: shift the input and the feature map shifts the same way — a feature detected in one place is detected identically everywhere. Together these cut parameters from the order of (inputs × outputs) down to the size of one small kernel.

In plain words GRADE 6

The picture: in a dense layer every output listens to every input — like a classroom where every student must hear every other student at once. In convolution, each output only listens to its few neighbours (sparse), everyone uses the same listening rule (shared), and if the whole class shuffles one seat over, the answers just shuffle one seat over too (equivariant).

So instead of memorising a special rule for every spot, the network learns one good rule and applies it everywhere — cheaper to store, faster to run, and it isn't fooled when the picture slides a little.

Summarise a neighbourhood · §9.3

Pooling

A typical convolutional stage runs in three steps: convolve to make feature maps, apply a nonlinearity (the detector stage), then pool. Pooling replaces each small neighbourhood of a feature map with a summary statistic — the maximum (max pooling) or the average (average pooling). Because a summary of a patch barely changes when the patch's contents shift by a pixel, pooling makes the representation approximately invariant to small translations. That is exactly what you want when you care whether a feature is present, not precisely where. Pooling with stride also shrinks the map, cutting later computation.

In plain words GRADE 6

The picture: squint at a picture. You lose the exact pixels but still see "there's an edge here, a bright spot there." Max pooling is like reporting the loudest thing in each little patch; average pooling reports the typical thing. Either way you keep the gist and drop the fussy detail.

The payoff: if the whole thing jiggles by a pixel, the loud thing is still the loudest, so the squinted answer barely changes. The network stops caring about tiny wobbles and focuses on what's actually there.

In practice Handles variable sizes too

Pooling over regions that scale with the input lets a network accept images of different sizes and still hand a fixed-size vector to the classifier — essential for real-world pipelines. Learned or overlapping pooling, and global average pooling before the final layer, are common modern choices.

Where the idea came from · §9.10

The Neuroscientific Basis

Convolutional networks are one of deep learning's clearest success stories drawn from neuroscience. In the 1960s Hubel and Wiesel recorded from a cat's primary visual cortex (area V1) and found cells arranged in a spatial map, each responding to light in a small patch of the visual field — its receptive field. Simple cells fired for edges at a particular orientation and position; complex cells responded to the same orientation but tolerated small shifts. Those two behaviours are almost exactly convolution (an oriented filter applied everywhere) followed by pooling (tolerance to position). Strikingly, the first-layer filters a CNN learns from data look like Gabor functions — the very oriented edge detectors seen in V1.

In plain words GRADE 6

The picture: deep in your brain, near the back of your head, there are cells that each get excited by a line tilted a certain way in one little corner of what you're looking at. One cell loves upright lines, another loves slanted ones. Stack their answers up and your brain starts to see shapes.

When we let a convolutional network teach itself to see, its very first detectors come out looking like those same brain cells — little tilted-line finders. Nobody programmed that in; the network rediscovered a solution evolution already found.

The analogy is real but loose. CNNs borrow V1's local oriented filtering and pooling, but skip most of the brain's biology — feedback connections, spikes, attention, and the rest of the visual pathway. Neuroscience seeded the architecture; engineering and data did the rest.

A prior baked into the wiring · §9.4

Convolution & Pooling as an Infinitely Strong Prior

A prior probability distribution encodes what we believe about a model's parameters before seeing any data. A weak prior (high variance) barely constrains the weights; a strong prior (low variance) pulls them hard toward certain values. Push this to the limit and you get an infinitely strong prior — one that assigns zero probability to some settings, forbidding them outright no matter what the data says. Here is the key reframing: a convolutional layer is just a fully-connected layer with an infinitely strong prior on its weights. That prior says two things: each unit's weights must be zero outside its small receptive field, and the weights must be identical to its neighbours' (shifted). Pooling is likewise an infinitely strong prior that each unit should be invariant to small translations.

In plain words GRADE 6

The picture: a prior is a belief you hold before looking. A gentle belief ("probably smallish weights") nudges you. An infinitely strong belief is a rule you refuse to break — "the answer must not depend on faraway pixels, and the same rule must apply everywhere." Convolution is a dense layer with those two rules locked in before any training begins.

That's powerful when the rules are true (they are, for images) — it saves huge effort. But if you forced these rules on data where they're wrong, the network would be crippled by its own confidence. A prior only helps when it matches reality.

Convolution = dense layer + infinitely strong prior on W
p(W) = 0 for weights outside the receptive field  ·  p(W) = 0 unless weights are shared across positions   ⟹  only local, tied weights survive

In practice A prior can misfire

Convolution's prior assumes translation is a symmetry of the task. When it isn't — say the top of an image means something different from the bottom — pure weight sharing can hurt, which is why locally connected and tiled variants exist (§07). Pooling's invariance prior can likewise discard position information a task actually needs.

Knobs on the basic operation · §9.5

Variants of the Basic Convolution Function

Real convolutional layers rarely use the textbook operation unchanged. A handful of knobs control how the kernel moves and what it covers. Stride skips positions to down-sample as you convolve. Padding adds a border (usually zeros) so the output can stay the same size ("same") instead of shrinking ("valid"). Dilation spreads the kernel's taps apart to enlarge the receptive field without adding weights. And convolution always runs over multiple input and output channels at once, so a layer's kernel is really a small 4-D tensor. Related variants — locally connected layers (local but unshared), tiled convolution (a rotating set of kernels), and grouped convolution — trade the sharing prior for flexibility or efficiency.

In plain words GRADE 6

The picture: the sliding tile has settings. Stride is how big a step it takes — bigger steps, smaller output. Padding is taping an extra blank border around the photo so the tile can reach the edges and the output doesn't shrink. Dilation is spreading the tile's holes apart so it peeks at a wider area while still using the same few weights.

Grouped / channels

Split channels into groups convolved separately for efficiency. In general a kernel spans all input channels and produces many output channels — a 4-D weight tensor.

Beyond one label · §9.6–9.7

Structured Outputs · Data Types & Channels

A convolutional network need not output a single class. Because convolution preserves spatial layout, it can emit a whole structured output — a tensor as large as the input. The classic case is semantic segmentation: label every pixel with the object it belongs to, producing a map the same shape as the image. The same machinery handles inputs of many shapes. Convolution is defined for data of any dimensionality, each axis a grid, plus a channel axis holding co-located measurements (the red, green and blue of a pixel; the two ears of stereo audio; the bands of a satellite image).

In plain words GRADE 6

The picture: sometimes the answer isn't one word ("cat") but a whole coloured-in map ("these pixels are road, these are sky, these are people"). And the input isn't always a photo — it can be a sound (a line of numbers), a photo (a grid), or a video or scan (a stack of grids). At each spot there can be several numbers at once — the channels, like the three colours in a pixel.

Structured outputs
  • Per-pixel labels — segmentation returns a class for every pixel; the output tensor matches the image's height and width.
  • Keep resolution — avoid heavy down-sampling, or up-sample back, so fine spatial detail survives to the output.
  • Refine iteratively — early architectures ran the same convolutions repeatedly to sharpen a pixel-label map.
  • Uses — medical organ/lesion outlining, self-driving scene parsing, satellite land-cover maps, pose and depth estimation.

Doing it fast · §9.8

Efficient Convolution Algorithms

Modern networks apply millions of convolutions, so the arithmetic matters. Several tricks make it cheaper. A separable kernel factors into the outer product of two 1-D kernels, so a d-dimensional convolution becomes a sequence of 1-D passes — a k×k filter drops from k² multiplies per pixel to just 2k. Large kernels can be applied in the frequency domain via the FFT, where convolution becomes cheap point-wise multiplication. And specialised routines (Winograd-style minimal-multiply algorithms, im2col + matrix multiply on GPUs) squeeze out more. These don't change what convolution computes — only how quickly.

In plain words GRADE 6

The picture: some big stamps can be done as two little swipes — first blur left-to-right, then blur top-to-bottom — and you get the exact same result with far less work. If a stamp can be split like that, splitting it is a bargain: a 9×9 stamp needs 81 multiplications per spot, but two swipes need only 18.

Cheap features · steady training · §9.9

Random / Unsupervised Features & Normalization

Training convolutional kernels by back-propagation is expensive, and it isn't the only option. Surprisingly, random filters already act as decent feature extractors — a bank of untrained convolutions still highlights edges, blobs and textures, and a classifier on top of random-plus-pooling features can do respectably. Unsupervised methods (clustering image patches with k-means, greedy layer-wise pretraining) learn filters without labels, cheaply. These approaches let you search architectures fast, or bootstrap when labelled data is scarce. Separately, deep stacks train far better with normalization: batch normalization re-centres and re-scales each layer's activations so their distribution stays stable, which speeds and steadies learning.

In plain words GRADE 6

The picture: even a stencil you cut at random catches some edges — so you don't always have to painstakingly design the first layer. And normalizing is like re-scaling everyone's scores each round so the next step isn't thrown off by wild swings; it keeps the numbers flowing through a deep network well-behaved.

The payoff · §9.11 & history

Applications in Computer Vision · ImageNet

Convolutional networks are the workhorse of modern computer vision. Stacked conv–pool stages build a hierarchy of features: the first layer finds oriented edges, the next combines them into corners and textures, later layers assemble object parts, and the top layers respond to whole objects. The turning point was ImageNet — a dataset of over a million labelled photos across a thousand categories — and its annual challenge (ILSVRC). In 2012, the convolutional network AlexNet cut the error rate so dramatically that deep learning became the default for vision almost overnight, and successive convolutional designs pushed accuracy past the previous state of the art year after year.

In plain words GRADE 6

The picture: the network sees in layers, like building with blocks. First it notices little lines. Then it snaps lines into corners and patterns. Then patterns into parts — an ear, a wheel. Then parts into a whole thing — a cat, a car. Each layer stands on the one below.

Then came a giant photo contest called ImageNet. In 2012 a convolutional network won it by a mile, and that single result convinced the world these networks were the way to make computers see.

The 2012 result reset the field — the ideas in this chapter, at scale, are what made computers competitive with humans on many visual tasks.

If you remember only one thing

A convolutional network is a neural network that bakes the structure of grid data into its wiring. By making connections local, sharing one small filter across every position, and pooling to tolerate small shifts, it slashes parameters, respects spatial layout, and gains translation tolerance. Read another way, convolution and pooling are infinitely strong priors — rules assumed before any data — and they happen to be true for images, audio and video. Stack these layers into a feature hierarchy, add enough data (ImageNet) and compute (GPUs), and you get the systems that gave machines sight.
