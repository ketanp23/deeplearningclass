Deep learning · Chapter 10 · How networks learn to remember

Read in order,
carry the past.

A recurrent neural network is a neural network built for data that arrives in order — words in a sentence, samples of speech, ticks of a time series. Instead of seeing the whole input at once, it steps through one element at a time and keeps a running summary of everything seen so far in a hidden state. At every step it mixes the new input with the old state to make a new state, reusing the same weights at every step. That single loop lets one small network handle sequences of any length and share what it learns across every position. But a plain loop struggles to hold information across long gaps — the problem that gated cells (LSTM, GRU) were invented to solve. 01
Role · significance · society · §10 intro

Sequence Learning & Why It Matters

A great deal of the world's data is ordered: the words of a sentence, the notes of a melody, the frames of a video, the daily readings of a sensor. In each case the meaning lives not in any single element but in the pattern over time — "not good" means the opposite of "good", and a heartbeat is normal or dangerous only in the context of the beats around it. A fixed-input network sees a flat list of numbers with no notion of order or of length, so it must relearn every pattern at every position and cannot accept inputs of varying size. A recurrent neural network attacks the problem directly: it reads the sequence one step at a time, carries a hidden state that summarises the past, and reuses one set of weights at every step. That makes it length-agnostic, order-aware, and parameter-thrifty — the combination that powered a decade of language, speech and time-series systems.

In plain words GRADE 6

The picture: reading a story is not the same as being handed a bag with all its words shuffled inside. Order carries the meaning. A recurrent network reads like you do — one word at a time — and keeps a little note to itself about what's happened so far. Each new word updates the note, and the note is what it uses to guess what comes next.

Because it keeps that running note, it can handle a short text or a long one with the same machinery, and it isn't confused when the same word shows up in a different spot. One reader, one notebook, any length of story — that's the whole idea, and it's why phones can predict your next word, apps can turn speech into text, and hospitals can watch a signal for danger.

What a fixed-input model gets wrong on sequences
  • Fixed length only — a dense layer needs a fixed-size input, so it can't naturally accept sentences or signals that vary in length.
  • No sense of order — flatten a sequence into one vector and "the dog bit the man" and "the man bit the dog" look almost the same; order information is thrown away.
  • No sharing across time — a feature useful at step 3 must be relearned separately for step 40; nothing is shared across positions.
  • Blind to context — the meaning of an element usually depends on its neighbours, which a position-by-position model can't see.
What recurrence builds in The three fixes

A hidden state (memory) — a vector carried from step to step summarises everything read so far, so the past can shape the present.

Weight sharing across time — the same transition function runs at every step, so a pattern learned once applies at every position and any length works.

Order sensitivity — because the state is updated left-to-right, swapping two elements changes the trajectory of the state, and therefore the output.

Significance & applicability — where RNNs solve real problems
❝

Language & translation

Language modelling, autocomplete, machine translation and summarisation — reading text as a sequence and generating the next token conditioned on all the previous ones.

♫

Speech recognition, keyword spotting, speaker diarisation and music generation, where the signal only makes sense as an ordered stream of samples.

◷

♡

✎

The core recurrence · §10.1

The RNN Model

At each time step t a recurrent network takes the current input xₜ and the previous hidden state hₜ₋₁, and produces a new hidden state hₜ by pushing their combination through a nonlinearity. The same weight matrices — one for the input (Wₓₕ), one for the recurrence (Wₕₕ) — are used at every step, so the whole model is one small cell applied over and over. An output yₜ can be read off the state at any step. Because hₜ depends on hₜ₋₁, which depends on hₜ₋₂, and so on, the hidden state at step t is in principle a summary of the entire history up to t. Drawing the same cell once per step turns the loop into a deep feed-forward graph — this is called unrolling.

In plain words GRADE 6

The picture: imagine one stamp-machine on a conveyor belt. Each item that rolls by (a word) gets stamped, and the machine also updates a little dial that remembers a summary of everything it has stamped so far. The same machine handles every item; it just keeps turning the dial.

To think about how it learns, you can "unroll" the belt: draw the one machine again and again, once for each item, connected in a line. Now it looks like a very deep ordinary network — and we already know how to train those.

Each new state blends the fresh input with a squashed copy of the old state. With a small gain the state fades quickly; near a gain of one it holds information longer — a hint of the memory problem to come.

In practice One cell, any length

Sharing Wₓₕ, Wₕₕ, Why across all steps is what lets a single trained RNN process a five-word tweet or a five-hundred-word review with no change. It also means the number of parameters does not grow with sequence length — only the depth of the unrolled graph does.

Output timing: you can emit an output at every step (tagging), only at the end (classification), or run the network as a generator that feeds its own output back in as the next input.
03
Training the loop · §10.2

Backpropagation Through Time

To train an RNN we unroll it into a deep feed-forward graph — one copy of the cell per time step — and run ordinary backpropagation on that graph. This procedure is called backpropagation through time (BPTT). The one twist is parameter sharing: because the same weight matrix appears at every step, its gradient is the sum of the contributions from every step where it was used. The loss at a late step therefore sends gradient signal back through every earlier step, and each of those steps also adds its own local contribution. Summing these correctly is all BPTT does — but the long chain of multiplications it creates is exactly what makes long sequences hard to train (§06).

In plain words GRADE 6

The picture: unroll the conveyor belt into a long line of identical machines. To improve the shared machine, you check every spot where it was used, ask "how should you have behaved here?", and then add up all those bits of advice into one update. Advice from far down the line has to travel back through many machines to get home.

The catch: as advice passes back through step after step, it can shrink until it's basically zero (the network forgets to learn long-range links) or blow up into nonsense. That travelling-back-and-multiplying is the heart of both how RNNs learn and why they struggle.

In practice Truncated BPTT

Running BPTT across a very long sequence is expensive in memory and time, and the far-back gradients are usually tiny anyway. Truncated BPTT processes the sequence in chunks, carrying the hidden state forward but only back-propagating a fixed number of steps — a practical compromise between cost and range.

04
Input/output shapes · §10.3

Different Types of RNNs

The same recurrent machinery can be wired to different input–output shapes, and the shape is chosen to match the task. A one-to-one map is just an ordinary network. One-to-many takes a single input and emits a sequence — image captioning turns one picture into a stream of words. Many-to-one reads a whole sequence and emits a single answer — sentiment from a review, a label from an audio clip. Many-to-many (aligned) emits one output per input — part-of-speech tagging, per-frame video labelling. And many-to-many (encoder–decoder / seq2seq) reads the entire input into a summary and then generates an output sequence of a different length — the classic recipe for machine translation.

In plain words GRADE 6

The picture: think of it as choosing how many things go in and how many come out. Sometimes you give one thing and want a whole story back (a photo → a caption). Sometimes you read a whole story and want one word back (a review → "happy" or "sad"). Sometimes you want one answer for every word (tag each word), and sometimes you read everything first, then say a new sentence in another language.

The reader-with-a-notebook is the same in every case. All that changes is when you let it read and when you make it speak.

Reading both ways · §10.4

Bidirectional RNNs

A plain RNN reads left-to-right, so its state at step t knows the past but nothing of the future. Yet for many labelling tasks the right answer depends on what comes after — the word "book" is a noun or a verb depending on the rest of the sentence. A bidirectional RNN runs two independent RNNs over the same sequence: one forward and one backward. At each position it concatenates the two hidden states, giving a representation that has seen the entire sequence — everything to the left through the forward pass and everything to the right through the backward pass. The cost is that the whole input must be available before you start, so bidirectional models suit offline labelling, not streaming, causal prediction.

In plain words GRADE 6

The picture: to understand a tricky word, you often need to peek ahead as well as remember what came before. A bidirectional network sends one reader forward through the sentence and a second reader backward, then lets them compare notes at every word. Now each word is understood using both its left and its right neighbours.

The trade-off: the backward reader has to start at the end, so you need the whole sentence first. Great for marking up text you already have; no good for guessing the very next word as someone types.

The core difficulty · §10.5

The Challenge of Long-Term Dependencies

The elegance of the recurrent loop hides a hard problem. When BPTT sends gradient back across many steps, it multiplies a long chain of Jacobians together. If the typical factor is a little less than one, the product shrinks toward zero after a few dozen steps — the vanishing gradient — and the network simply cannot learn dependencies that span long gaps. If the factor is a little greater than one, the product blows up — the exploding gradient — and training becomes unstable. Because tanh and sigmoid have derivatives at most one (and usually much less), plain RNNs sit on the vanishing side by default: they remember the recent past well but forget the distant past. This single fact motivates everything that follows — gated cells, gradient clipping, and better initialisation.

In plain words GRADE 6

The picture: whisper a message down a long line of people, where each person makes it a little quieter. After enough people it's silence — that's a vanishing gradient, and it means the network never learns that something early mattered for something much later. Make each person a little louder instead and the message becomes a deafening mess — an exploding gradient.

Plain networks tend toward the "gets quieter" side, so they're forgetful over long gaps. The fix isn't to whisper harder; it's to build a special memory lane where the message can travel without being turned down — which is exactly what LSTMs and GRUs add.

In practice Two different fixes

Exploding gradients are treated cheaply by gradient clipping — rescale the gradient when its norm crosses a threshold (§09). Vanishing gradients need an architectural fix: a memory path where the signal is added and gated rather than repeatedly multiplied, which is exactly the idea behind the LSTM cell.

A cell that remembers · §10.6

Long Short-Term Memory (LSTM)

The LSTM (Hochreiter & Schmidhuber, 1997) fixes the vanishing gradient by adding a protected memory track — the cell state cₜ — that information can ride along almost untouched. Three learned gates control it: the forget gate fₜ decides how much of the old memory to keep, the input gate iₜ decides how much new candidate content to write, and the output gate oₜ decides how much of the memory to expose as the hidden state. Crucially, the cell updates by addition — cₜ = fₜ·cₜ₋₁ + iₜ·g̃ₜ — not by repeated matrix multiplication. When the forget gate stays near one, the cell carries its value forward with the gradient essentially undiminished. That protected additive path is often called the constant error carousel, and it is why LSTMs learn dependencies hundreds of steps long.

In plain words GRADE 6

The picture: give the reader a lockbox for important notes. Three little switches decide what happens each step: one says "keep what's in the box" (or clear it), one says "put this new note in", and one says "let me peek at the box right now". Because the box is added to rather than rewritten from scratch, a note can sit there untouched for a very long time.

That protected box is the whole trick. A plain network's memory leaks a little every step until it's gone; the LSTM's box can hold a fact steady across a long story, so it finally learns links between things that are far apart.

Slide the forget gate to exactly one and the stored value never fades — memory and its gradient are preserved indefinitely. That is the property a plain RNN cannot have.

In practice Learned, not set by hand

In a real LSTM the gates are not knobs — they are computed from xₜ and hₜ₋₁ through learned weights, so the cell decides per input when to remember, overwrite, or release. A common trick is to initialise the forget-gate bias positive so the cell defaults to remembering early in training.

A lighter gate · §10.7

Gated Recurrent Unit (GRU)

The GRU (Cho et al., 2014) keeps the LSTM's key idea — gated, additive memory — but with a simpler design and fewer parameters. It drops the separate cell state and merges the forget and input gates into a single update gate zₜ, which interpolates directly between the old hidden state and a fresh candidate: hₜ = (1−zₜ)·hₜ₋₁ + zₜ·h̃ₜ. A second reset gate rₜ controls how much of the previous state feeds into that candidate, letting the unit ignore its past when a new context begins. With two gates instead of three and no distinct memory cell, a GRU is cheaper to compute and often trains faster, while matching LSTM quality on many tasks — though LSTMs still hold an edge on some very long or complex sequences.

In plain words GRADE 6

The picture: the GRU uses one main dial — "how much of today's news should replace yesterday's summary?" Turn it low and it mostly keeps the old summary (strong memory); turn it high and it mostly takes the fresh version. A second little switch lets it decide how much of the old summary to even look at when forming today's news.

It's the LSTM idea with fewer parts: one blend dial instead of two separate keep/write switches, and no separate lockbox. Simpler to build, quick to train, and usually just as good.

Training in practice · §10.8

Learning Algorithm of RNN / LSTM

Recurrent networks — plain, LSTM or GRU — are all trained the same way: unroll through time and run BPTT to get gradients, then update with an optimiser such as SGD, RMSProp or Adam. Four practical ingredients make it work. Truncated BPTT keeps memory and cost bounded on long sequences. Gradient clipping tames the exploding-gradient cliffs by rescaling the gradient whenever its norm exceeds a threshold. Gating (LSTM/GRU) plus careful initialisation counters the vanishing side. And for generative RNNs, teacher forcing feeds the true previous token during training so the model learns from correct context, rather than compounding its own early mistakes. Together these turn a fragile loop into something trainable.

In plain words GRADE 6

The picture: training an RNN is like teaching someone to walk a cliff-edge path. Sometimes the ground is smooth, but occasionally there's a sudden drop where one big step sends you flying. Gradient clipping is a leash: no matter how steep it gets, you're only allowed to take a step of a certain size, so you never launch off the cliff.

The other tricks: don't re-derive advice from the whole endless path each time (do it in chunks); use the lockbox cells so lessons from long ago don't fade; and while teaching a story-writer, feed it the correct next word so it doesn't practise on its own mistakes.

Two directions, gated memory · §10.9

Bidirectional LSTMs

A bidirectional LSTM (BiLSTM) simply combines the two ideas that fixed the biggest problems: it runs an LSTM forward and a second LSTM backward over the sequence, and concatenates their states at each position. This gives every position access to the entire sequence (from bidirectionality) and the ability to carry information across long gaps in each direction (from the gated cell). For years the BiLSTM — often stacked and topped with a CRF layer — was the default for sequence labelling: part-of-speech tagging, named-entity recognition, and acoustic modelling in speech. It resolves ambiguities that need future context while still remembering distant cues, at the price of requiring the whole input up front.

In plain words GRADE 6

The picture: take the two readers who go forward and backward (bidirectional), and give each of them the memory lockbox (LSTM). Now, to label a tricky word, the network can both remember something important from far earlier and peek at what's coming — from either direction, across any distance.

Is "book" a noun or a verb? "I want to book a flight" is clear only from the words after it. A bidirectional reader with memory catches that easily, which is why this design was the workhorse for tagging and speech for a long time.

In practice Where it fits

Use a BiLSTM when the whole sequence is known in advance and every position needs full context — tagging, parsing, offline speech. Do not use it for real-time generation or forecasting, where the future genuinely isn't available yet; there a forward (causal) LSTM/GRU is required.

From chains to trees · §10.10

Recursive Neural Networks

A recurrent network is a chain: it applies the same cell along a straight line of time steps. A recursive neural network generalises this to a tree: the same composition function is applied over a hierarchical structure, merging two child representations into a parent, bottom-up, until a single vector represents the whole structure. This matches data that is naturally nested — the parse tree of a sentence, the structure of a program, a scene graph. A key advantage is depth: for a sequence of length n, a balanced tree has depth on the order of log n rather than n, so information travels through far fewer steps between distant leaves — easing the long-dependency problem. A standard RNN is in fact the special case of a recursive net applied to a purely left-branching (chain) tree.

In plain words GRADE 6

The picture: instead of reading words one after another in a line, imagine combining them the way a sentence is actually built — small phrases join into bigger phrases, which join into the whole sentence, like a family tree. The same "combine two things into one" rule is used at every join.

The bonus: in a bushy tree, even far-apart words meet after only a few joins (about log n), instead of passing through every word in between. Fewer steps between distant pieces means less chance for the signal to fade.

In practice Structure has a cost

The catch is that you need that structure, and irregular trees are harder to batch efficiently, which is one reason chain RNNs and, later, attention models became more popular for general text.

If you remember only one thing

A recurrent network turns a loop into memory: it reads a sequence one step at a time and carries a hidden state that summarises the past, reusing one set of weights at every step. Train it by unrolling through time and back-propagating — but that same long chain of multiplications makes distant gradients vanish or explode, so a plain RNN is short-sighted. The cure is a gated, additive memory path — the LSTM's cell state and the GRU's update gate — that lets information (and its gradient) ride across long gaps. Add a second, backward pass for full context (bidirectional), or compose over a tree instead of a chain (recursive), and you have the family of models that gave machines a memory for order.

01

Ordered data → carry a state

Fixed-input models ignore order and length; recurrence keeps a running summary and shares weights across every step.

02

hₜ = f(hₜ₋₁, xₜ)

One small cell, applied over and over; the hidden state is the network's memory of everything read so far.

03

BPTT = unroll & sum

Backprop on the unrolled graph; a shared weight's gradient sums contributions from every time step.

04

Shapes fit the task

One-to-many, many-to-one, aligned many-to-many, and encoder–decoder seq2seq choose when to read and when to speak.

05

Read both ways

A bidirectional RNN concatenates a forward and a backward pass, giving each position the whole sequence as context.

06

Long gaps are hard

The product of Jacobians vanishes (<1) or explodes (>1); plain RNNs forget the distant past.

07

LSTM & GRU fix memory

Gated, additive cells protect the gradient path — the forget gate near one keeps memory alive across hundreds of steps.

08

Train with care · go bushy

Truncated BPTT, gradient clipping and teacher forcing make training stable; recursive trees give log-depth paths between distant elements.
